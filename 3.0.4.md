## 1. Problém — root cause

ZION L1 má **dva paralelní transakční modely**:

| Model | Struct | Memo? | Kdo používá |
|-------|--------|-------|-------------|
| **UTXO** | `tx::Transaction` (`V3/L1/core/src/tx.rs:40-54`) | ✅ `TxOutput.memo: Option<String>` | Bridge lock, atomic swap, DAO vote, WARP — všechny memo-protokoly |
| **Account** | `Transaction` (`V3/L1/core/src/lib.rs:383-398`) | ❌ žádné memo pole | Běžné wallet převody, coinbase |

**Důsledek:** Account-model TXs nemohou nést `BRIDGE:`, `SWAP:`, `DAO:`, `WARP:` instrukce. Tři L2 watchery (bridge, dao, atomic-swap) záměrně parší jen `utxo_transactions` pole bloku a account TXs ignorují — protože nemají co číst.

Tohle je dokumentováno jako "Known limitation" v `AGENTS.md` a jako "ROADMAP ITEM (L1 HARD FORK REQUIRED)" v `V3/ROADMAP.md` řádcích 62 a 71.

**Cíl 3.0.4:** Sjednotit oba modely tak, aby account-model TXs mohly nést memo data, a všechny watchery skenovaly oba typy. Tím se odstraní nutnost uživatelům používat UTXO TXs pro memo-protokoly.

## 3. Design — dvě možnosti

### Možnost A: Přidat `memo` do account TX (doporučeno)

Přidat `memo: Option<String>` do account `Transaction` structu, analogicky k UTXO `TxOutput.memo`.

**Pros:**
- Minimální změna — jedno nové pole
- Symetrie s UTXO modelem (stejný typ, stejná sémantika)
- Watchery jen přidají druhý loop přes `block.transactions`
- Memo formáty zůstávají identické (`BRIDGE:`, `SWAP:`, atd.)

**Cons:**
- Mění tx_id hash preimage → **hard fork**
- Mění body root (už stejně pokrývá account TXs, ale hash se změní)
- Staré account TXs bez memo se musí deserializovat s `#[serde(default)]`

**Způsob aktivace:** Stejný pattern jako `TX_HASH_V2` — nový háček `ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT`. Před aktivací memo pole ignoruje hash; po aktivaci se memo stává součástí preimage. Tím se vyhneme nutnosti rehashovat historii.

### Možnost B: Sjednotit na jeden model (zamítnuto)

Zrušit account model a vše převést na UTXO, nebo naopak.

**Cons:**
- Katastrofálně invazivní — každý wallet, SDK, explorer, pool by se přepsal
- Account model má výhody pro nonce-based replay protection
- UTXO model má výhody pro bridge unlock proof
- Riziko konsenzového rozkladu obrovské

**Verdikt:** Možnost A. Minimální, symetrická, reversibilní.

## 4. Doporučený přístup — Možnost A s height-gated aktivací

### 4.1 Nový konsenzový háček

V `V3/L1/cosmic-harmony/src/deeksha.rs` přidat (analogicky k `TX_HASH_V2`):

```rust
pub const ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT: u64 = 0; // nebo koordinovaná výška

pub fn account_tx_memo_v1_active(height: u64) -> bool {
    height >= ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT
}
```

> **L1 consensus change — vyžaduje human approval.**

### 4.2 Account Transaction struct

V `V3/L1/core/src/lib.rs:383-398` přidat:

```rust
pub struct Transaction {
    // ... existující pole ...
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub memo: Option<String>,
}
```

`#[serde(default)]` zaručuje backward-compatible deserializaci starých TXs.

### 4.3 Hash preimage

`Transaction::compute_tx_id()` (kde se počítá tx_id) musí:
- Před `ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT`: memo **ignorovat** (staré chování)
- Po aktivaci: memo **zahrnout** do preimage

Tohle je klíčový bod hard forku — staré uzly počítají jiný tx_id pro stejnou TX s memo.

### 4.4 Validace

`Transaction::validate()` (`lib.rs:1907-1933`) přidat:
- `memo.as_ref().map(|m| m.len() <= 256)` — limit na 256 bytes (stejně jako UTXO)
- `memo.as_ref().map(|m| m.is_ascii())` — nebo povolit UTF-8, rozhodnutí pro ownera

### 4.5 Signatura

`Transaction::verify_signature()` (`lib.rs:1938-1963`) — signatura je přes `tx_id`. Protože `tx_id` už zahrnuje memo (po aktivaci), signatura memo pokrývá automaticky. **Žádná extra změna** kromě toho, že `compute_tx_id` musí memo zahrnout.

### 4.6 Merkle root

`derive_template_merkle_root_v2_blake3()` (`lib.rs:3853-3866`) už zahrnuje account TXs přes `transaction.tx_id`. Protože tx_id se mění (zahrnuje memo), merkle root se mění automaticky. **Žádná extra změna.**

### 4.7 RPC

`getBlock` RPC už vrací celý `AcceptedBlock` včetně `transactions` s novým memo polem. **Žádná změna v L1 RPC** — serde automaticky serializuje nové pole.

Volitelné: přidat `send_transaction` RPC endpoint, který akceptuje memo (už pravděpodobně existuje, jen rozšířit o memo parametr).

## 5. L2 Watchery — rozšíření skenování

Každý ze tří watcherů musí:

1. Rozšířit `L1Block` struct o `transactions: Vec<AccountTransaction>` (kromě `utxo_transactions`)
2. Definovat `AccountTransaction` s `from, to, amount, memo` poli
3. Přidat druhý loop: `for tx in &block.transactions { if let Some(memo) = &tx.memo { ... } }`
4. Sdílet memo parser s existující UTXO cestou

### 5.1 Bridge watcher

**Soubor:** `V3/L2/bridge/src/l1_watcher.rs`

```rust
#[derive(Debug, Deserialize)]
struct L1Block {
    pub height: u64,
    #[serde(alias = "hash_hex")]
    pub hash: String,
    #[serde(default)]
    pub utxo_transactions: Vec<L1Transaction>,
    #[serde(default)]
    pub transactions: Vec<L1AccountTransaction>,  // NOVÉ
}

#[derive(Debug, Deserialize)]
struct L1AccountTransaction {
    pub from: String,
    pub to: String,
    #[serde(default)]
    pub memo: Option<String>,
}
```

Skenování: vedle `for tx in &block.utxo_transactions` přidat `for tx in &block.transactions` a aplikovat `parse_bridge_memo()` na `tx.memo`.

### 5.2 DAO scanner

**Soubor:** `V3/L2/dao/src/l1_scanner.rs` — analogicky, rozšířit `BlockInfo` o `transactions` a přidat loop s `parse_dao_memo()`.

### 5.3 Atomic swap watcher

**Soubor:** `V3/L2/atomic-swap/src/types.rs` + `watcher.rs` — analogicky, rozšířit `L1Block` o `transactions` a přidat loop s `SwapMemo::parse()`.

> **Pozn:** U account TXs není `inputs`/`outputs` — memo je na úrovni celé TX, ne na output. Watchery musí brát memo z `tx.memo`, ne z `tx.outputs[i].memo`. Tohle je sémantický rozdíl: UTXO memo je per-output, account memo je per-TX. Pro memo-protokoly to nevadí (vždy se používá jeden memo na TX).

## 8. Hard fork aktivace

### 8.1 Aktivace od genesis (doporučeno pro čistý mainnet)

Pokud je mainnet ještě v rané fázi (height ~21000, malý počet účastníků), nejjednodušší je aktivovat `ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT = 0` — memo je součástí hash od začátku. Tohle vyžaduje:

- Restart všech uzlů s novým binárním souborem
- Rehash historie NENÍ potřeba (staré TXs nemají memo, `#[serde(default)]` je načte jako `None`, hash se přepočítá konzistentně na obou stranách)

> **Otázka pro ownera:** Je mainnet dostatečně malý na koordinovaný restart? Nebo potřebujeme height-gated aktivaci (soft-fork style)?

### 8.2 Height-gated aktivace (pokud restart není možný)

`ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT = <future_height>` — uzly začnou počítat hash s memo až od dané výšky. Předtím memo ignorují. Vyžaduje koordinovaný upgrade všech uzlů před aktivací.

### 8.3 Rollback

- DB backup před cutover: `edge-state.db.bak-3.0.4-memo`
- Pokud se něco rozbije, vrátit starý binární soubor + DB backup
- Memo pole je additive — staré uzly nové TXs s memo odmítnou (neznají pole), ale nezhavarují (serde `default`)

## 11. Rizika

| Riziko | Pravděp. | Dopad | Mitigace |
|--------|----------|-------|----------|
| Hard fork rozkol (uzly neupgradují) | Střední | Konsenzové rozvětvení | Koordinovaný upgrade všech uzlů před aktivací; mainnet je malý (~3 uzly) |
| Hash mismatch staré vs nové uzly | Vysoká | Fork | Height-gated aktivace; `#[serde(default)]` pro staré TXs |
| Memo spam (velké memy) | Nízká | Bloat chain | Limit 256 bytes, validace v `Transaction::validate()` |
| Watcher double-count (UTXO + account se stejným memo) | Střední | Double mint / double vote | Watchery musí deduplikovat podle (tx_id, memo) — UTXO tx_id ≠ account tx_id |
| Signatura ne pokrývá memo | Vysoká | Tx malleability | `compute_tx_id` musí memo zahrnout PŘED signaturou — test `test_account_tx_memo_in_signature` |
| Bridge `BRIDGE_UNLOCK:` na account TX | Nízká | Konsenzová chyba | `BRIDGE_UNLOCK:` je L1 consensus memo, ne L2 watcher — ověřit že bridge.rs parser zpracuje account TX |

## 12. Otázky pro ownera (blockery)

1. **Aktivace:** `ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT = 0` (restart) nebo `= <future>` (height-gated)? Mainnet má ~3 uzly, restart je proveditelný.
2. **Memo charset:** ASCII-only nebo UTF-8? (UTXO memo je dnes `String` — UTF-8, ale memo formáty jsou ASCII prefixy.)
3. **Memo limit:** 256 bytes (jako UTXO) nebo jiný?
4. **`BRIDGE_UNLOCK:` na account TX:** Povolit, nebo nechat jen na UTXO? (Bridge unlock je konsenzově kritický — možná bezpečnější držet UTXO.)
5. **L1 approval:** Tento plán popisuje editaci `V3/L1/core/src/`. Per AGENTS.md §"L1 Protocol Security Protocol" vyžaduje explicitní written approval. Schvaluje owner implementaci?
