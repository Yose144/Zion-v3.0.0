## 3. TX Unification — UTXO ↔ Account (📋 PLÁN — čeká na schválení)

> **Status:** Plán napsán, implementace čeká na schválení 5 blokujících otázek (§3.7)
> **L1 consensus change = hard fork** — vyžaduje explicitní written approval per AGENTS.md

### 3.1 Problém — root cause

ZION L1 má **dva paralelní transakční modely**:

| Model | Struct | Memo? | Kdo používá |
|-------|--------|-------|-------------|
| **UTXO** | `tx::Transaction` (`V3/L1/core/src/tx.rs:40-54`) | ✅ `TxOutput.memo: Option<String>` | Bridge lock, atomic swap, DAO vote, WARP — všechny memo-protokoly |
| **Account** | `Transaction` (`V3/L1/core/src/lib.rs:383-398`) | ❌ žádné memo pole | Běžné wallet převody, coinbase |

**Důsledek:** Account-model TXs nemohou nést `BRIDGE:`, `SWAP:`, `DAO:`, `WARP:` instrukce. Tři L2 watchery (bridge, dao, atomic-swap) parší jen `utxo_transactions` a account TXs ignorují.

### 3.2 Řešení — Možnost A (doporučeno)

Přidat `memo: Option<String>` do account `Transaction` structu, analogicky k UTXO `TxOutput.memo`.

```rust
pub struct Transaction {
    // ... existující pole ...
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub memo: Option<String>,
}
```

**Způsob aktivace:** Height-gated háček `ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT` (stejný pattern jako `TX_HASH_V2`). Před aktivací memo ignoruje hash; po aktivaci se memo stává součástí preimage.

**Možnost B (zamítnuto):** Sjednotit na jeden model — katastrofálně invazivní, každý wallet/SDK/explorer by se přepsal.

### 3.3 Memo formáty v produkci

| Prefix | Formát | Writer | Reader |
|--------|--------|--------|--------|
| `BRIDGE:` | `BRIDGE:<chain>:<evm_addr>` | user wallet | bridge watcher (`l1_watcher.rs:374`) |
| `BRIDGE_UNLOCK:` | `BRIDGE_UNLOCK:<src>:<burn_id>:<tx_hash>\|PROOFS=...` | L1 bridge builder (`bridge.rs:107`) | L1 consensus (`bridge.rs:148`) |
| `SWAP:` | `SWAP:LOCK:<hash>:<timeout>:<chain>:<addr>`, `SWAP:CLAIM:...`, `SWAP:REFUND:...` | atomic swap users | atomic-swap watcher (`types.rs:196-243`) |
| `DAO:` | `DAO:vote:<id>:yes/no/abstain`, `DAO:guardian:register:<pubkey>` | DAO voters | DAO scanner (`dao/types.rs:49`) |
| `WARP:` | `WARP:<ver>:<chain>:<recipient>[:opts]` | WARP users | WARP router (`protocol.rs:73`) |

### 3.4 Watchery — všichni tři skenují jen UTXO

| Watcher | Soubor | L1Block struct | Skenuje |
|---------|--------|----------------|---------|
| Bridge | `V3/L2/bridge/src/l1_watcher.rs:58-64` | `L1Block { utxo_transactions }` | `block.utxo_transactions` |
| DAO | `V3/L2/dao/src/l1_scanner.rs:51-55` | `BlockInfo { utxo_transactions }` | `block.utxo_transactions` |
| Atomic swap | `V3/L2/atomic-swap/src/types.rs:323-329` | `L1Block { utxo_transactions }` | `block.utxo_transactions` |

Po unifikaci každý watcher přidá druhý loop přes `block.transactions` a aplikuje stejný memo parser.

### 3.6 Rizika

| Riziko | Pravděp. | Dopad | Mitigace |
|--------|----------|-------|----------|
| Hard fork rozkol | Střední | Konsenzové rozvětvení | Koordinovaný upgrade; mainnet ~3 uzly |
| Hash mismatch staré vs nové uzly | Vysoká | Fork | Height-gated aktivace; `#[serde(default)]` |
| Memo spam | Nízká | Bloat chain | Limit 256 bytes |
| Watcher double-count | Střední | Double mint/vote | Deduplikace podle (tx_id, memo) |
| Signatura nepokrývá memo | Vysoká | Tx malleability | `compute_tx_id` musí memo zahrnout PŘED signaturou |
| `BRIDGE_UNLOCK:` na account TX | Nízká | Konsenzová chyba | Doporučeno nechat jen na UTXO |

### 3.7 Otázky pro ownera (blockery implementace)

1. **Aktivace:** `ACCOUNT_TX_MEMO_V1_ACTIVATION_HEIGHT = 0` (restart) nebo `= <future>` (height-gated)?
2. **Memo charset:** ASCII-only nebo UTF-8?
3. **Memo limit:** 256 bytes (jako UTXO) nebo jiný?
4. **`BRIDGE_UNLOCK:` na account TX:** Povolit, nebo nechat jen na UTXO? (Konsenzově kritické — doporučeno UTXO only.)
5. **L1 approval:** Schvaluje owner implementaci? (Per AGENTS.md §"L1 Protocol Security Protocol")

### 4.2 Native ZION naming convention (✅ COMPLETE 2026-07-01)

> **Koncept:** [`docs/3.0.3/nativeZion.md`](./docs/3.0.3/nativeZion.md) — WARP přenáší **native L1 ZION**, ne wZION. "w" prefix je Ethereum konvence (WETH, WBTC) — na non-EVM chainech nedává smysl, tam je to prostě **ZION**.

WARP přenáší **native L1 ZION**. wZION je jen wrapped reprezentace na EVM chainech (jako WBTC na Ethereum).

#### Token naming convention

| Chain type | Token name | Proč |
|-----------|-----------|------|

| **Solana** | **ZION** | SPL token — nativní reprezentace |
| **Tron** | **ZION** | TRC-20 — nativní reprezentace |

| **Cosmos** | **ZION** | CosmWASM contract — nativní reprezentace |
| **Cardano** | **ZION** | Native token (policy_id + asset_name) |
| **Aptos** | **ZION** | Move module — nativní reprezentace |
| **Sui** | **ZION** | Move module — nativní reprezentace |
| **NEAR** | **ZION** | NEAR contract — nativní reprezentace |
| **TON** | **ZION** | Jetton — nativní reprezentace |
| **Lightning** | (BTC) | HTLC — direct BTC channel, no token |

#### WARP Bridge Architecture

**Outbound (ZION L1 → external chain):**
1. Uživatel pošle ZION L1 TX → output na `BRIDGE_VAULT_ADDRESS` + memo `BRIDGE:<dest_chain>:<recipient>`
2. L1 node zaznamená "bridge lock" — **ZION se zamkne** v bridge vault (`getBridgeLocks` RPC)
3. WARP watcher detekuje lock → router vytvoří outbound transfer
4. WARP validator set podepíše mint instruction (quorum 3/5)
5. WARP adapter na dest chain → `execute_mint()` → **mintne ZION** (nebo **wZION** na EVM) recipientovi (1:1 peg)

**Inbound (external chain → ZION L1):**
1. Uživatel **spálí** ZION/wZION na external chain (`bridgeBurn` na EVM, ekvivalent na non-EVM)
2. WARP watcher detekuje burn event → router vytvoří inbound transfer
3. WARP validator set podepíše unlock instruction (quorum 3/5)
4. WARP zavolá `submitBridgeUnlock` na L1 node → **odemkne ZION** z bridge vault → recipient

#### L1 RPC endpointy (již implementováno v `V3/L1/core/src/rpc.rs`)

- `getBridgeLocks(from_height, to_height)` — scan bloků pro TX s output na BRIDGE_VAULT_ADDRESS
- `getBridgeVaultBalance()` — celkový ZION zamčený v bridge vault
- `submitBridgeUnlock(recipient, amount_flowers, burn_id, evm_chain, evm_tx_hash, validator_proofs)` — uvolní ZION z vault (vyžaduje 3/5 validator signatures)
