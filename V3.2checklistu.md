## C. Restart nodu / UTXO stav

- [x] Root cause doložen: `Node::new` při každém startu replayuje celý chain do in-memory `UtxoSet` a znovu ověřuje podpisy.
- [x] Watchdog během CPU-heavy rebuildu už proces nerestartuje (`busy` guard), takže se neopakuje incidentální kill-loop.
- [x] Perzistentní odvozená UTXO cache svázaná s výškou a tip hashem implementována.
- [x] Cache delta je v jedné SQLite transakci se zápisem bloku/tipu/indexů; stale/malformed/count mismatch cache se invaliduje a bezpečně se replayuje vlastní block store.
- [x] Trusted replay přeskakuje pouze podpis/HTLC script execution; strukturální, sum, fee, address a admin-unlock pravidla zůstávají. Live/mempool validace zůstává plná.
- [x] Regresní testy: round-trip, stale tip, corrupted cache, HTLC script, admin unlock, incremental update, missing input invalidace a transakční rollback. `zion-core`: 337 pass, clippy bez warningů.
- [x] Opraven pre-existing duplicate-input inflation bug (`AlreadySpent` před součtem); read-only audit produkční historie: 62 953 bloků, 113 374 transakcí, 116 050 vstupů, 0 duplicitních vstupů.
- [x] Benchmark na konzistentní kopii produkční node3 DB (height 62 960, integrity OK): cold rebuild 7,54 s, warm cache start 0,89 s; cache 231 271 výstupů, DB +47,4 MB.
- [ ] Canary rollout: node3 → node2 → primary; vždy ověřit výšku, tip hash, UTXO balances a sync před dalším krokem.
- [ ] Produkční důkaz restartu pod 5 minut. Lokální benchmark splnil aspiraci pod 60 sekund, ale produkční položka se označí až po canary.
