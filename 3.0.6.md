## 3-Stream Parallel Mining Architecture

```
┌──────────────────────────────────────────────────────────────────┐
│                        zion-miner process                         │
│                                                                  │
│  STREAM 1 (GPU)          STREAM 2 (GPU)         STREAM 3 (CPU)   │
│  ┌──────────────┐        ┌──────────────┐      ┌──────────────┐  │
│  │ ZION Deeksha │        │ Pearl PoUW   │      │ Verus / XMR  │  │
│  │ (primary)    │        │ (secondary)  │      │ (tertiary)   │  │
│  │              │        │              │      │              │  │
│  │ OpenCL ctx A │        │ OpenCL ctx B │      │ CPU threads  │  │
│  │ deeksha_lite │        │ pearl_pouw   │      │ verushash /  │  │
│  │ work_size    │        │ _real_pouw   │      │ randomx      │  │
│  │ 262144       │        │ work_size    │      │              │  │
│  │              │        │ 262144       │      │              │  │
│  └──────┬───────┘        └──────┬───────┘      └──────┬───────┘  │
│         │                       │                     │          │
│         │  All shares via ZION pool (single TCP conn) │          │
│         └───────────────────────┼─────────────────────┘          │
│                                 ▼                                │
│                    62.171.141.136:8444                           │
│                      ZION stratum pool                           │
│                                                                  │
│  Pool I/O Thread (main)                                          │
│  ├── reads ZION Job (with embedded external_stream)             │
│  ├── if external_stream.coin == "PRL":                          │
│  │     → dispatch to Pearl GPU thread (Stream 2)                 │
│  ├── elif external_stream.algorithm is CPU-only:                │
│  │     → dispatch to tertiary CPU thread (Stream 3)              │
│  ├── else (GPU-capable external):                               │
│  │     → dispatch to secondary GPU thread                        │
│  ├── scans Deeksha on GPU primary (Stream 1)                    │
│  ├── submits ZION shares (Submit → Result)                      │
│  └── submits external shares (ExternalSubmit → ExternalResult)  │
│                                                                  │
│  Pearl GPU Thread (persistent, own OpenCL context)              │
│  ├── recv PearlJob from channel (from external_stream)          │
│  ├── mine PoUW on GPU secondary (pearl_real_pouw.rs)            │
│  └── send PearlProof to main thread → PearlSubmit               │
│                                                                  │
│  Tertiary CPU Thread (persistent)                               │
│  ├── recv ExternalStreamJob from channel                        │
│  ├── scan on CPU (verushash / randomx)                         │
│  └── send ExternalShareResult to main thread → ExternalSubmit   │
└──────────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
┌──────────────────────────────────────────────────────────────────┐
│                    ZION POOL (62.171.141.136:8444)               │
│                                                                  │
│  AuxPowBridge (background, connects to ALL external pools):      │
│  ├── VRSC pool (LuckPool) → verushash jobs                     │
│  ├── PRL pool (AlphaPool) → pearl.challenge jobs               │
│  ├── DCR pool (Woolypooly) → blake3 jobs                       │
│  ├── KAS pool → kheavyhash jobs                                │
│  ├── RVN pool → kawpow jobs                                    │
│  ├── ERG pool → autolykos jobs                                 │
│  └── ... (auto profit-switching every 5 min)                    │
│                                                                  │
│  Revenue tracking:                                               │
│  - routing_snapshot: per-source share counts (17 sources)       │
│  - src_zion, src_pearl, src_verushash, src_blake3, etc.         │
│  - Pool fee on ALL external revenue (2% default)                │
│  - PPLNS distribution includes external revenue                 │
│  - Dashboard reads from /stats endpoint (port 8455)             │
└──────────────────────────────────────────────────────────────────┘
```

### Stream Detail

| Stream | Algorithm | Hardware | Coin(s) | Status | Pool |
|--------|-----------|----------|---------|--------|------|
| 1 (Primary) | `deeksha_lite_v1` | GPU (OpenCL ctx A) | ZION | ✅ Live | ZION stratum (direct) |
| 2 (Secondary) | `pearlhash` (PoUW) | GPU (OpenCL ctx B) / CPU fallback | PRL | ✅ Live | ZION pool → AlphaPool |
| 3 (Tertiary) | `verushash` / `randomx` | CPU threads | VRSC / XMR | ✅ Live | ZION pool → LuckPool / MoneroOcean |
| 3 (GPU ext) | `blake3` / `kheavyhash` / `kawpow` / `autolykos` / `ethash` / `zelhash` / `progpow` | GPU secondary slot | DCR / KAS / RVN / ERG / ETC / FLUX / EPIC | ✅ Live (excl. EPIC) | ZION pool → external |

**GPU scheduling:** AMD Vega 64 (gfx900) — 64 CUs, 8GB VRAM
- Deeksha kernel: ~4GB VRAM (scratchpad), ~5ms per batch
- Pearl kernel: ~2GB VRAM (matrices), ~50ms per attempt
- Both run concurrently via OpenCL hardware scheduler

### Block Reward Distribution (Protocol-Level)

| Recipient | Share | Amount (per block) | Notes |
|-----------|-------|--------------------|-------|
| **Miner** (PPLNS) | 89% | 4,806.06 ZION | Distributed proportionally via PPLNS window |

| **Issobella** (L6) | 5% | 270.00 ZION | Space layer funding |
| **Burn** 🔥 | 1% | 54.00 ZION | Permanently destroyed (never minted) |
| **Total** | 100% | 5,400.067 ZION | Base reward, Decade 1 |

**Emission schedule:** Decade Decay — reward × (4/5) every 5,256,000 blocks (10 years).
After decade 10: perpetual tail emission of 724.785 ZION/block.

### External Revenue (AuxPow Bridge)

| Source | Pool Fee | Notes |
|--------|----------|-------|
| ZION (primary) | 5% (merged mining) | Core block reward |
| Pearl (PRL) | 2% (profit switch) | PoUW proofs via AlphaPool |
| Verus (VRSC) | 2% (profit switch) | CPU VerusHash v2.2 |
| Monero (XMR) | 2% (profit switch) | CPU RandomX |
| Decred (DCR) | 2% (blake3 external) | GPU Blake3 |
| Kaspa (KAS) | 2% (profit switch) | GPU kHeavyHash |
| All other external | 2% (profit switch) | Auto profit-switching |

**External revenue flow:**
1. Miner finds external share → submits to ZION pool
2. Pool forwards to external pool via AuxPowBridge
3. External pool accepts → pool records in `routing_snapshot`
4. Pool deducts 2% fee → remainder added to PPLNS distribution
5. PPLNS miners receive proportional share of external revenue
6. Dashboard shows per-source revenue in Revenue tab

### PPLNS Engine

| Property | Value |
|----------|-------|
| Window size | 500,000 shares (configurable via `ZION_PPLNS_WINDOW_SIZE`) |
| Share weighting | Difficulty-weighted (diff 1000 = 1000× weight) |
| Miner ID | u32 interning (zero-allocation hot path) |
| Max throughput | 50,000 shares/sec at 10k miners |
| State persistence | JSON file at `ZION_PPLNS_STATE_PATH` |
| Snapshot | Backward-compatible String-based format |

## Pool Protocol Messages

```rust
enum PoolMessage {
    Hello { miner_id, worker_name, algorithm, payout_address, backend }
    Welcome { protocol_version, algorithm, job_ttl_ms }
    Job { job_id, algorithm, start_nonce, nonce_count, target_hex, header_hex, height, stream_weights, external_stream }
    Submit { job_id, nonce, hash_hex }
    Result { accepted, status, block_height, block_hash }
```

## E2E Edge Server Audit (2026-07-15)

### Live Pool Status

- **ZION shares:** 44,950 submitted, 44,938 accepted (99.97% accept rate)

### VRSC Share Acceptance — ✅ FIXED (2026-07-16)

`routing_snapshot` previously showed `src_verushash=0` — external shares were NOT being submitted. Root cause was twofold:

1. **Outdated miner binary** — missing `clear_verushash_pbaas()` (PBaaS v7+ header normalization before VerusHash). Without this, miner's hash never matched LuckPool's `verusHashV2b2` validation → `low difficulty share` rejection.
2. **TriGpuManager Cpu bug** — `TriGpuManager::new(Cpu, ...)` crashed with "GPU backend requested but kind=cpu", preventing CPU-only miner startup.

**Fix deployed 2026-07-16:** Recompiled `zion-miner` with `native-verushash` feature + `clear_verushash_pbaas` fix. TriGpuManager Cpu kind handled gracefully. Legacy `zion-pool.service` disabled (port 8444 conflict with `zion-edge-pool.service`).

**Result:** 4/4 VRSC shares accepted by LuckPool, 0 rejections. See [`docs/3.0.5/VRSC_SHARE_ACCEPTANCE_FIX_2026-07-16.md`](./docs/3.0.5/VRSC_SHARE_ACCEPTANCE_FIX_2026-07-16.md).

### VRSC Performance Optimization — ✅ 2.7x speedup (2026-07-16)

After share acceptance was fixed, benchmarked against **hellcatz/hminer v0.59.1** (hellminer — the fastest closed-source CPU VerusHash miner). Hellminer achieved 0.669 MH/s on 3 threads vs our 0.280 MH/s on 4 threads (2.4x faster).

**Root cause of slowness:**
1. **Missing AVX2/BMI/BMI2 build flags** — only SSE4.1/AES/PCLMUL were enabled
2. **Full hash per nonce** — miner hashed entire 1487-byte header per nonce (~324 Haraka calls). Hellminer/bloxminer use **two-stage mining**: `hash_half` (once per job) + `hash_with_nonce` (only ~2 Haraka calls per nonce)

**Fix:**
- Added `-mavx -mavx2 -mbmi -mbmi2` to `native-ffi/build.rs` for x86_64
- Implemented two-stage mining FFI in `ffi_wrapper_v3.cpp`:
  - `verushash_hash_half()` — Haraka512 chain → 64-byte intermediate (ONCE per job)
  - `verushash_prepare_key()` — GenNewCLKey from intermediate (ONCE per job)
  - `verushash_hash_with_nonce()` — CLHash + final Haraka512 (PER NONCE)
- `scan_verushash()` in `miner_harness.rs` now dispatches to `scan_verushash_two_stage()` when `native-verushash` is enabled

**Benchmark results (AMD EPYC 4-core, 3 threads):**

| Miner | Hashrate | Notes |
|-------|----------|-------|
| ZION miner (before) | 0.280 MH/s | Full hash, no AVX2 |
| ZION miner (after) | **0.746 MH/s** | Two-stage + AVX2 |
| hellminer v0.59.1 | 0.669 MH/s | Closed-source reference |

**Result:** 5 VRSC shares in 4 minutes, all accepted by LuckPool with two-stage path. See [`docs/3.0.5/VRSC_PERF_OPTIMIZATION_2026-07-16.md`](./docs/3.0.5/VRSC_PERF_OPTIMIZATION_2026-07-16.md).

### RandomX Performance Optimization — ✅ 23x speedup (2026-07-16)

After VRSC optimization, benchmarked RandomX (XMR) against **XMRig v6.21.3** — the gold standard XMR miner. XMRig achieved 245 H/s on 3 threads vs our **7 H/s** on 4 threads (35x faster!).

**Root cause of slowness (3 issues):**
1. **Missing AES-NI flag** — `hard_aes=no` → soft AES fallback (~10x slower). Build flags only had SSE4.1, not `-maes`
2. **Missing AVX2/BMI/BMI2 flags** — `argon2_avx2.c` compiled without AVX2 → slow cache init
3. **`hash_with_seed(&[])` reinit bug** — benchmark called `hash_with_seed` with empty seed, which reinitialized the 2GB dataset on **every hash call** (instead of once)

**Fix:**
- Added `-maes -msse4.2 -mavx -mavx2 -mbmi -mbmi2` to `native-ffi/build.rs` for x86_64 RandomX build
- Added `RANDOMX_FLAG_LARGE_PAGES` to `get_vm_flags()` + `alloc_flags` in `randomx_wrapper.cpp` — enables 2MB huge pages for dataset (reduces TLB misses ~20-30%)
- Fixed `randomx_zion_init()` — skip reinit if seed is empty and already initialized
- Fixed `hash_with_seed()` in Rust FFI — skip `init_with_seed` if seed is empty
- Fixed benchmark to use `hash()` instead of `hash_with_seed(&[], ...)`
- Configured `vm.nr_hugepages=1250` on Edge server (persisted in `/etc/sysctl.d/99-hugepages.conf`)

**Benchmark results (AMD EPYC 4-core, 4 threads):**

| Miner | Hashrate | Threads | Notes |
|-------|----------|---------|-------|
| ZION miner (before) | 7 H/s | 4 | No AES-NI, no huge pages, reinit bug |
| ZION miner (after AES-NI + huge pages) | 41 H/s | 4 | hard_aes=yes, large_pages=yes |
| ZION miner (after reinit bug fix) | **161 H/s** | 4 | 23x total speedup |
| XMRig v6.21.3 | 245 H/s | 3 | Reference (MSR mod failed on VPS) |

**Result:** 23x speedup (7→161 H/s). XMRig is still 1.5x faster per-thread (82 vs 40 H/s) due to MSR mod and optimized assembly. See [`docs/3.0.5/RANDOMX_PERF_OPTIMIZATION_2026-07-16.md`](./docs/3.0.5/RANDOMX_PERF_OPTIMIZATION_2026-07-16.md).
