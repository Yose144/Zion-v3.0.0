## Key Fix: CUDA Arch Auto-Detect

### Problem
All CUDA kernels (deeksha_lite_fire, deeksha_lite, cosmic_harmony_deeksha, ethash, kawpow, etc.) were hardcoded to compile for `sm_86` (Ampere/RTX 30xx). On GTX 1080 (Pascal, sm_61), NVRTC compilation succeeded but PTX JIT failed:

```
gpu_init_fallback reason="PTX load failed: DriverError(CUDA_ERROR_INVALID_PTX)" using=cpu
```

This caused **all GPU streams to fall back to CPU**, making the GPU useless.

### Fix
Added `detect_cuda_arch()` function that queries the GPU's compute capability via `CU_DEVICE_ATTRIBUTE_COMPUTE_CAPABILITY_MAJOR/MINOR` and generates the correct `sm_XX` string for NVRTC.

**Files changed:**
- `V3/L1/miner/src/cuda_external.rs` — added `detect_cuda_arch()`, replaced 2 hardcoded `sm_86` defaults
- `V3/L1/miner/src/gpu_backend.rs` — added `detect_cuda_arch()` at module level, replaced 3 hardcoded `sm_86` defaults (cuda_deeksha, cuda_deeksha_lite_fire, cuda_deeksha_lite)

**Priority:** `ZION_CUDA_ARCH` env var > auto-detect > `sm_86` fallback

**Result:**
```
cuda_arch_detect: compute_capability=6.1 => arch=sm_61
gpu_cuda_fire_init device="NVIDIA GeForce GTX 1080" work_size=4096 scratchpad_mb=1024
gpu_init backend=cuda device="NVIDIA GeForce GTX 1080" work_size=4096 algorithm=deeksha_lite_fire streams=3
dual_gpu_check gpu_available=true gpu_backend=Cuda => dual_gpu_enabled=true
stream2_gpu_external_started work_size=262144
```

Now compatible with: Pascal (sm_61), Turing (sm_75), Ampere (sm_86), Ada (sm_89), Hopper (sm_90), and any future CUDA arch.
