# Hiran Audit — 2026-10-10 (pre-Maestro 2.4)

> Komplexní audit Hiran stacku: kód `V31/L3/ai-native`, Edge deployment,
> inference path, dataset rebuild, 2.4 Maestro readiness. Data pro
> orchestraci: **`service-map.json`** (machine-readable, verifikováno live).

## 1. TL;DR

Maestro je **v kódu kompletní** (intent→plan→DAG→tools→result, 537 ř. +
planner 829 + tool_registry 1554 + layer_agents 613 + health_poller 919 +
intent 996) — ale **není mountnutý** v `:8001` API a jeho tool/probe layer
**nechytá se živých služeb**: dvě vrstvy chyb — zastaralé porty (známých 11
z WIRING_MAP) **a navíc špatné RPC metody/cesty** (V3-era bitcoin-style
`getblockcount` vs V31 camelCase `getChainInfo`; `/proposals` vs
`/api/dao/...`; `/sessions` vs `/miners`). Inference za `:8002` tunelem je
aktuálně DOWN. Dataset rebuild: **7 059 párů** (v21_curriculum 2880 +
qwen3_gen 2640 + V3 scrape/manual ~1492).

## 4. Bezpečnostní nálezy

1. **`:8899` = `python3 http.server` "rig-exfil"** — POST receiver zapisující
   body do `/root/rig-exfil/`, listen `0.0.0.0`, bez auth. Pravděpodobně ops
   hack pro dumpy z rigů, ale **veřejně dostupný write-endpoint** → doporučení:
   potvrdit účel, jinak bind→127.0.0.1 nebo zabít.
2. `/mnt/data` (1.8T NTFS backup disk) **není připojen — `/dev/sdb` úplně
   chybí v lsblk** → backup pipeline nemá cíl (fail-soft → logy ukážou errors,
   žádný alarm). Ověřit v Contabo panelu / dmesg.
3. `execute_plan` auto-approves `requires_approval` kroky (maestro.rs:214) —
   před mountnutím na HTTP povinný mutation gate (§5.3).
4. `docker_restart_container` tool → `unix://` endpoint přes reqwest =
   nefunkční (reqwest neumí unix sockets) → drop nebo rewrite přes socket.
5. `:8002` tunnel = jediná inference cesta → single point of failure; řeší
   lokální rig (§6).

## 5. Maestro 2.4 — readiness + prep plan

### 5.1 Co je ready
- orchestrate() E2E flow + testy (maestro suity zelené v kódu)
- intent→sub-agent→tool mapping kompletní; approval flags na mutacích
- `HybridBackend::from_env` + `IntentRouter::with_llm` — LLM upgradepath hotová
- `with_audit_dir` vzor z orchestrator.rs pro plan audit

### 5.2 Implementační kroky (pořadí)

1. **`endpoints.rs`** — `Endpoints::from_env()` single-source (env_block
   v service-map.json); `ToolRegistry::with_env(&endpoints)` +
   `HealthPoller::with_endpoints(&endpoints)`; const defaults = live map.
2. **Tool/probe rewrite** — tabulka §3 (metody + cesty + porty); systemd
   probe typ pro portless služby; quantus/zis/grafana/marketplace add.
3. **`/v2` mount na :8001** (varianta A z WIRING_MAP — sdílí state):
   `POST /v2/orchestrate|plan|classify`, `GET /v2/health-matrix|info|tools`.
   Gate `HIRAN_MAESTRO_ENABLED=1`. Maestro do `AppState` (registry sdílená,
   ne per-request `with_all_tools`).
4. **Mutation gate:** `HIRAN_MAESTRO_MUTATIONS=0` default → mutating tools
   (Post/Put/Delete na ctrl endpoints + `requires_approval`) →
   `Skipped{reason:"mutations disabled"}`; `=1` + `X-Maestro-Approve:
   $MAESTRO_APPROVAL_TOKEN` → povolí, audit záznam.
5. **Audit JSONL** `ZION_L3_AUDIT_DIR=/opt/zion/data/l3-audit` — plan+steps+
   approvals+latency per run; přidat do backup staging (až /mnt/data žije).
6. **Resilience:** per-service circuit breaker (3 fail/60 s → open 120 s),
   semafor ~8 na tools, health cache 30 s TTL + last-good.
7. **LLM synthesis:** `compose_response` → `HiranInferenceClient` s template
   fallback; `IntentRouter::with_llm(RemoteHttpBackend)` když `use_llm=1`.
8. **Dharma hooks:** pre-check před mutating step (validate intent text),
   post-check na response.
9. **Deploy:** rebuild Edge binary (29 modulů — Edge má 28), atomic swap,
   env do unit drop-in; ověření §7 WIRING_MAP.

### 5.3 Interface contract (už fixované — viz service-map.json `ai_interface_contract`)

## 6. Inference plán — lokální rig ~14 GB VRAM (RX 5600 XT gfx1010 + Vega 64 gfx900)

**Karta rozložení:** Vega64 8 GB HBM2 (gfx900, GCN5) + RX 5600 XT 6 GB (gfx1010, RDNA1).
Max single-card = 8 GB → volba mezi split nebo 2-modely.

**Backend:** **llama.cpp Vulkan** — jediný praktický: gfx900 z ROCm 6+ ven,
gfx1010 nikdy oficiálně (HSA_OVERRIDE_GFX_VERSION=10.3.0 fungovalo do ~5.7);
Vulkan přes RADV podporuje obě, multi-GPU `--tensor-split`. HIP/ROCm 5.7.1
alternativa (gfx900 nativní + gfx1010 override) — křehčí stack.
SMOS = Ubuntu 20.04 → Mesa/RADV přes ppa:kisak nebo standalone binárka.

**Doporučená topologie (2 modely, bez splitu):**
- **gfx900 (Vega 8G):** Qwen3-8B **Q5_K_M ~5.7 GB** (+8k ctx Q8 KV ~1.2 GB)
  → Maestro core / reasoning. ~15-25 tok/s (HBM2 484 GB/s).
- **gfx1010 (5600XT 6G):** Qwen3-4B **Q4_K_M ~2.5 GB** nebo Qwen3-1.7B Q8
  → intent router / rychlý classify / dataset syntéza. ~30-50 tok/s.
- Výhoda vs split: dva nezávislé servery = router neblokuje core, selhání
  jednoho GPU nezabije oba; odpovídá designu (8B router + velký core).

**Alternativa (split):** Qwen3-14B Q4_K_M ~9.2 GB `--tensor-split 60,40`
→ jeden silnější core, ale router pak běží na CPU nebo sdílí sloty.

**⚠️ Kolize s minerem:** stejný rig teď minuje Quad (ZANO+QTU na obou
kartách). Inference vyžaduje miner pauzu/rekonfiguraci — buď dedikované
okno, nebo rig přeřadit z mining na AI roli (rozhodnout: tento rig je
"pak" = po mining fázi?).

**Servisní obal:** `llama-server --model ... -ngl 99 --port 8002` ×2
(porty 8002 core / 8012 router) + systemd user unit + stávající
`hirantunnel` reverse-forward → Edge :8002 (už existuje! stačí nastavit
na správný local port). OpenAI contract → drop-in pro :8001 `LLM_BASE_URL`
i desktop agenta. **Alias `zion-l3` zachovat** (a/nebo přidat `hiran-v2.2`
kvůli desktop IPC).
