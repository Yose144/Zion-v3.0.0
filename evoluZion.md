## Evoluce: Od PoW k Protokolu Péče

### Fáze 1: PoW — Dětství (současnost, 2026)
ZION L1 běží na Proof-of-Work s algoritmem Cosmic Harmony:
- **Deeksha Lite V1** — CPU/GPU friendly, scratchpad-based
- **Cosmic Harmony Ekam Deeksha V2** — pokročilý, AES + thermal loop
- **Deeksha Lite Fire** — thermal-intensive, 512 KiB scratchpad
- Decentralizované těžení — každý může těžit s CPU nebo GPU
- Emission schedule: 89% miner / 5% humanitarian / 5% DAO / 1% pool fee

**Smysl:** Bootstrapping sítě, distribuce mincí, budování komunity.

### Fáze 2: Hybrid — Adolescence (2027, plánováno)
**PoW + Proof-of-Care (PoC) hybrid:**
- PoW nadále běží pro decentralizaci a bootstrapping
- Proof-of-Care se přidává jako druhý layer — NPU validátory
- NPU (Neural Processing Unit) weights = nový "hashrate"
- Místo surové výpočetní síly → **caring computation** — AI inference která pomáhá síti
- Hiran v2.2 modely běží na NPU a produkují "care proofs"

**Co je "caring computation":**
- AI inference pro fraud detection na WARP bridge
- Cross-chain arbitrage detection (ochrana uživatelů)
- Liquidity rebalancing mezi 13 chainy
- Anomaly detection na L1 (double-spend, reorg attempts)
- AI-powered smart contract auditing
- Každý "care proof" = užitečná práce pro síť, ne waste energy

### Fáze 3: Protokol Péče — Dospělost (2028+, evoluce)
**Plný přechod z PoW na Proof-of-Care (PoC):**

#### Co se změní
- **Těžení = péče** — místo hashrate se měří "care score"
- **NPU weights** = nový mining hardware (ne GPU, ne ASIC, ale AI čipy)
- **AI automatizace** — validátory běží autonomně, AI optimalizuje
- **Energie** — radikálně nižší než PoW (NPU inference vs brute-force hashing)
- **Užitečná práce** — každý blok obsahuje care proofs (AI práce pro síť)

## NPU Mining — technická vize

### Co je NPU
NPU (Neural Processing Unit) = specializovaný čip pro AI inference:
- **Apple Neural Engine** (ANE) — v každém iPhone/Mac
- **Google TPU** — Tensor Processing Unit
- **NVIDIA Tensor Cores** — v GPU
- **Qualcomm Hexagon DSP** — v Android telefonech
- **Intel NPU** — v Meteor Lake+ CPU
- **Edge AI čipy** — Rockchip RK3588, etc.

### NPU jako mining hardware
Místo drahých GPU rigů:
- **Telefon** s NPU → může těžit ZION (care proofs)
- **Laptop** s NPU → může těžit ZION
- **Edge server** s NPU → enterprise mining
- **Cloud NPU** → rented mining

**Demokratizace těžení:**
- Dnes: kdo má nejvíce peněz na GPU → těží nejvíce
- Protokol Péče: kdo má nejlepší AI model + NPU → těží nejvíce
- Každý telefon se stává potenciálním validátorem

### Care Proof — technická specifikace (koncept)

```rust
struct CareProof {
    // Kdo produkoval proof
    validator_id: String,
    // Jaký care task byl proveden
    task_type: CareTask,
    // AI model použitý (Hiran version)
    model_hash: [u8; 32],
    // Vstupní data (network state, bridge TXs, etc.)
    input_hash: [u8; 32],
    // AI output (anomaly score, audit result, etc.)
    output: Vec<u8>,
    // NPU signature (proof that inference was done on real NPU)
    npu_attestation: NpuAttestation,
    // Care score (accuracy + timeliness + coverage)
    care_score: u64,
}

enum CareTask {
    WarpBridgeAudit,      // Audit WARP transferů
    CrossChainAnomaly,    // Detekce anomálií mezi chainy
    LiquidityHealth,      // Health check ZionDex poolů
    SmartContractVerify,  // Verifikace smart kontraktů
    HiranInference,       // AI inference pro Hiran
    BridgeRebalance,      // Optimalizace WARP likvidity
}
```

## Filozofie Péče

### Co znamená "péče" v kontextu blockchainu

**PoW** = síla (kdo má největší hashrate, ten vyhrává)
**PoS** = kapitál (kdo má nejvíce tokenů, ten vyhrává)
**PoC (Proof-of-Care)** = péče (kdo nejlépe opékuje síť, ten vyhrává)

**Péče znamená:**
- 🛡️ **Ochrana** — AI detekuje fraud, anomálie, útoky
- 🌿 **Péče o likviditu** — AI rebalancuje pooly na 13 chainech
- 🔗 **Péče o bridge** — AI audituje WARP transfery
- 🧠 **Péče o inteligenci** — AI inference pro Hiran
- 💚 **Péče o komunitu** — AI pomáhá uživatelům navigovat cross-chain
- 🌍 **Péče o planetu** — NPU = řádově méně energie než PoW

### Etický rozměr

**PoW kritika:** "Waste of energy, no useful output"
**PoS kritika:** "Rich get richer, capital concentration"
**PoC odpověď:** "Every block produces useful AI work that benefits the entire network"

Každý blok ZION L1 v Protokolu Péče obsahuje:
- Transakce (jako dnes)
- **Care proofs** — AI práce která pomohla síti
- **Health metrics** — stav 13 chainů
- **Anomaly reports** — detekované hrozby

**ZION L1 se stává živým organismem** — každý blok je nejen finanční transakce, ale i péče o ekosystém.

### 2. NPU Hardware Mining Theory — technický základ

**`docs/NPU_HARDWARE_MINING_THEORY.md`** (2026-04-02, 445 řádků):
Detailní technická studie o NPU mining. Klíčové koncepty:

- **RandomNPU** — generovat náhodné neuronové sítě per epoch (jako RandomX pro Monero, ale pro NPU)
- **NPU HW landscape:** Apple ANE (38 TOPS), Intel NPU (48 TOPS), AMD XDNA 2 (50 TOPS), Qualcomm Hexagon (45 TOPS)
- **Klíčový paradox:** "General-purpose NPU = existující komerční čip → mining na consumer HW, žádná ASIC výhoda"
- **RandomNPU princip:** ASIC který zvládne náhodný compute graf = general-purpose NPU = komerční čip → žádná ASIC výhoda
- **Neural Memory-Hard:** integrovat MLP do scratchpad passes — 3 simultánní ASIC bottlenecky (memory + compute + flexibility)
- **ZION NPU VM Spec:** INT8 deterministic VM s kanonickým chováním (bit-exact na všem HW)

**Klíčový závěr studie:**
> *"Samotná velikost NPU (větší matice) nepomůže. ASIC resistance vyžaduje randomizaci compute grafu — nikoliv jen vah, ale struktury výpočtu. To je přesně to, co dělá RandomX pro x86: generuje náhodné programy, takže ASIC musí být general-purpose CPU. RandomNPU by dělal totéž pro neuronové inference."*
