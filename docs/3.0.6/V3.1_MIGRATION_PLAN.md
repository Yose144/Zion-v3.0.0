# V3.1 Migration Plan — Clean `V31/` Tree

> **Goal:** Migrate the ZION mainnet code into a **brand-new, clean `V31/` directory inside this repo**, built on a dedicated branch. `V31/` is a *pure-code* rebuild — free of ballast, dead code, and duplication — with a corrected layer structure for **Mainnet Alpha (3.1.0)**.
>
> **Strategy:** New directory + new branch, NOT an in-place `git mv` reorg of `V3/`. The current `V3/` keeps running production while `V31/` is assembled and verified.
>
> **Timing:** Migration **begins after 3.0.9 "Pre-Alpha Hardening" is done** ([`3.0.9.md`](./3.0.9.md)). Until then this is a planning document only — no directories are moved.
>
> **Status:** 🔵 Planning (pre-3.0.9)  
> **Update 2026-07-27:** L2 structure under review for unification into a single **Multi-Chain** crate (`V31/L2/multichain`) per [`MAINNET_ALPHA_L2_UNIFICATION.md`](../../MAINNET_ALPHA_L2_UNIFICATION.md). This migration plan will be adjusted to reflect the unified target before implementation.

## 1. Why a clean `V31/` directory (not in-place reorg)

`V3/` grew organically across the 2.9.x → 3.0.6 lineage and now carries structural debt: duplicated external-coin logic, WARP in the wrong layer, ZionDex outside the workspace, and mixed research/ballast. Rather than risk a fragile in-place `git mv` reorg on the production tree, we **build a fresh `V31/` next to it** and migrate only clean, verified code.

| Benefit | Why it matters |
|---------|----------------|
| **Production stays live** | `V3/` keeps building and running on Edge during the whole migration. |
| **Only clean code moves** | We copy code deliberately, dropping dead code, duplication, and ballast — nothing is carried over "by accident". |
| **No broken intermediate states** | `main` is never half-migrated; the switch to `V31/` happens once it is green. |
| **Reviewable** | The migration branch shows exactly what was brought over and what was dropped. |
| **Reversible** | If anything is wrong, `V3/` is still the source of truth until we cut over. |

### The three moves + one merge

1. **AuxPow → miner (merge).** Eliminate the standalone root `AuXpow/` crate; its stratum clients, share forwarders, and GPU kernels become part of `V31/L1/miner/`. `ExternalCoin`/`CoinProfile`/`RevenueSource` stay canonical in `cosmic-harmony` — no duplication.
2. **WARP: L3 → L2 (move).** WARP is a bridge; it belongs beside `bridge/` so L1↔external value transfer is unified natively under L2.
3. **ZionDex: root → L2 (move).** Cross-chain DEX becomes a workspace member under L2 next to the bridge/warp/swap-aggregator it depends on.
4. **L3 = AI only.** `ai-native`, `ncl`, `hiran`, `orchestrator`, `automation`, `poc`.

### Superstructures stay

- **L4 Oasis, L5 Free World, L6 Issobella remain their own top layers.** They are product/mission superstructures built *on top of* L1–L3, not AI internals. They are migrated into `V31/` with the same layer identity (cleaned of dead code, but not merged into L3).

## 6. Branch & directory strategy

1. **Branch:** create `v3.1-migration` from `main` after 3.0.9 tag.
2. **Directory:** create empty `V31/` on that branch; assemble the workspace incrementally.
3. **Copy strategy:** use `git mv`/`git cp`-style moves where history matters (WARP, ZionDex, AuxPow), and clean copies for the rest. Prefer preserving history for the big moves.
4. **CI:** add a `V31/**` CI job (check, clippy, fmt, test) alongside the existing `V3/**` job so both trees are green during transition.
5. **Cutover:** once `V31/` is fully green and E2E-verified, `V3/` is archived (tag `pre-v3.1-cutover`) and `V31/` becomes canonical. Optionally rename `V31/` → `V3/` at the very end, or keep `V31/` as the launch name for 3.1.0.
6. **Public subtree:** update `public/` to mirror the clean `V31/` MIT-safe subset; verify diff before publishing.

## 10. Risks & mitigation

| Risk | Mitigation |
|------|------------|
| Two trees (`V3/` + `V31/`) drift during transition | Keep migration window short; freeze non-critical `V3/` changes; port only critical hotfixes to both. |
| AuxPow merge produces a huge, hard-to-review diff | Merge one external-coin family at a time on the migration branch. |
| WARP move breaks 499+ tests | Move with history, run WARP test suite after the move, fix imports incrementally. |
| ZionDex has a separate build/Foundry config | Bring `foundry.toml` under `V31/L2/ziondex/contracts/`; add a workspace CI step. |
| Superstructures L4–L6 accidentally folded into L3 | Explicit rule: L4/L5/L6 keep their own top-level layer; only AI internals live in L3. |
| Public subtree desync | `git subtree push --dry-run` + diff before publishing the clean tree. |
| Docs go stale | Rewrite `V31/README.md` + `V31/ROADMAP.md` in the same branch; update root pointers at cutover. |
