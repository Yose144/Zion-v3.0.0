# K1.2 merge runbook — root workspace (jeden lockfile)

> **Větev:** `k12-root-workspace` (2 commity: `f969f15ff` K1.2, `3045861e5` K1.4-lite)
> **Report:** [`docs/3.2/REPORTS/REPORT_2026-11-01_KINGDOM_K1.2_ROOT_WORKSPACE.md`](../REPORTS/REPORT_2026-11-01_KINGDOM_K1.2_ROOT_WORKSPACE.md)
> **Proč runbook:** merge mění `node_modules` layout celému repu. Nesmí proběhnout, když v `apps/**` běží build — a to se v tomhle repu děje často.

## 0. Podmínka vpředu (nepřeskakovat)

```bash
# 1. Nikdo nebuildí a nikdo necommituje
ps aux | grep -E "next build|npm run build|tsc -p" | grep -v grep          # musí být prázdné
git status --short | grep -E "^\s*M" | head                                # vědět, čí WIP v tree je
date +%H:%M:%S; git log -1 --format='%ad %s' --date=format:%H:%M:%S        # poslední commit
# 2. Poslední změna souborů je starší než ~10 min
find . -path ./.git -prune -o -newermt "-10 minutes" -type f -name "*.ts*" -print | grep -v node_modules | head
```

Když cokoli z toho nesedí, **počkej**. Okno potřebuje ~10 minut klidu.

## 1. Merge (bez konfliktů)

Kolize ověřena 2026-11-01 12:38 — main od odbočení nezměnil ani jeden soubor větve:

```bash
git checkout main
git merge --no-ff k12-root-workspace -m "K1.2+K1.4: root workspace (jeden lockfile), three 0.186, sdk z workspace"
```

## 2. Root install (5 min, tady to bolí)

```bash
cd /home/zionserver/2.9.6-main
npm ci                 # jeden lockfile, 2031 balíčků; postinstall vygeneruje prisma client
```

`npm ci` **nesahá** na `apps/*/node_modules` — ty zůstanou jako staré stromy. To je nebezpečné: app by dál resolvovala `three@0.169` ze svého stromu a `apps/shared/**` z rootu (`three@0.186`) → přesně ta chyba s `FogExp2`, která shodila build OasisWeb.

```bash
# 3. Zlikvidovat staré per-app stromy (jen u 6 webů; mobil/Electron/identita mají vlastní)
for a in pool-ui IntroPage MarketPlace nirvana OasisWeb website-v2.9 shared zion-wallet-sdk; do
  rm -rf "apps/$a/node_modules"
done
```

Teprve po zeleném smoke testu nasazovat ostatní (`deploy-oasis-web.sh`, `deploy-web2.9.sh`, `deploy-nirvana.sh`, `deploy-marketplace.sh`). Každý má vlastní zálohu/rollback — vypíše je na konci.

## 5. Rollback

```bash
# celý merge
git reset --hard ORIG_HEAD          # nebo konkrétní commit před mergem
rm -rf node_modules
for a in pool-ui IntroPage MarketPlace nirvana OasisWeb website-v2.9 shared zion-wallet-sdk; do
  (cd "apps/$a" && npm install)     # obnoví per-app stromy ze starých lockfilů (ty merge vrátí)
done
```

Pozor: staré per-app `package-lock.json` se mergem **smažou**, ale `git reset --hard` je vrátí — proto rollback funguje jen přes gitu, ne ručním mazáním souborů.
