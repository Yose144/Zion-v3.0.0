# REPORT — HA fencing (W2.2 / G11): promote bez tokenu je neplatný (2026-11-01)

> **Zadání:** udělat z runbooku §4 vynutitelnou podmínku. Cíl: promote standby poolu
> nesmí jít provést omylem, protože dvě instance platící ze stejné peněženky = dvojí výplata
> a payout historie se zpětně needituje.
> **Výsledek:** `pool-promote-guard.sh` s šesti guardy, **22/22 testů**, live `--check` na
> produkci = **BLOKOVÁNO** (správně). Promote zůstává manuální — armed/auto-promote **neexistuje**,
> ale obchvat už není možný bez explicitního zásahu do kódu.

## 1. Co guard vynucuje

| | Podmínka | Zdroj důkazu |
|---|---|---|
| **G1** | primár prokazatelně mrtvý — unit **inactive** *a* žádný `zion-pool` proces | `systemctl is-active` + `pgrep -af zion-pool` na primáru |
| **G2** | auto-restart primáru vypnutý | `zion-v31-watchdog.timer` = inactive (jinak by pool vzkřísil) |
| **G3** | stratum primáru zavřený | TCP `62.171.141.136:8444` neodpovídá |
| **G4** | parita doložená | `dr-parity-check.sh --only data` bez `FAIL` |
| **G5** | žádný jiný promote neběží | single-flight token (atomic `O_EXCL`, TTL 900 s) |
| **G6** | cooldown | ≥ 600 s od minulého pokusu |

Klíčové rozlišení: **degradace není smrt.** Wedged API nebo pomalý disk se řeší `systemctl restart`
na primáru; guard G1 zablokuje (unit/proces žije). Fail-closed: když primár nejde ověřit, G1 selže.

## 2. Režimy

```bash
pool-promote-guard.sh --check     # exit 0 = povoleno, 1 = blokováno (nic nemění)
pool-promote-guard.sh --promote   # + fencing token, audit, výpis kroků runbooku §6
pool-promote-guard.sh --release   # zruší token (lokálně i na standby)
pool-promote-guard.sh --status    # token, cooldown, poslední audit
pool-promote-guard.sh --quiet     # jeden řádek pro alerty
```

Audit: `promote-audit.jsonl` (ts, epoch, actor, mode, verdict, detail) — každý pokus,
i odmítnutý. Token: `promote.token` (JSON, epoch + actor + TTL), atomicky přes `set -C`.

## 3. Read-only sonda primáru (bez root shellu)

Guard běží tam, kde je standby i token, ale musí vidět stav primáru. EDGE2 dnes na primár
nedosáhne (`:22` refused, `:2222` publickey denied). Místo root klíče je nasazený **omezený klíč**:

- na EDGE: `/usr/local/sbin/edge-pool-probe.sh` — jediné, co klíč umí (forced command),
  vrací `unit=… proc=… timer=…`,
- v `/root/.ssh/authorized_keys` (EDGE) záznam s
  `command="…edge-pool-probe.sh",no-port-forwarding,no-agent-forwarding,no-pty,no-X11-forwarding,from="207.180.217.100"`,
- klíč `/etc/zion/keys/edge-probe` (0600) na EDGE2, cesta v `/etc/zion/pool-standby.env`
  (`ZION_POOL_HA_PROBE_CMD`),
- setup/reprodukce: `infra/tools/pool-ha/setup-fencing-key.sh` (idempotentní, zálohuje `authorized_keys`),
- rollback: smazat jeden řádek z `authorized_keys` na EDGE.

`grep -q zion-pool-fencing-probe /root/.ssh/authorized_keys` = trust existuje.

## 4. Ověření

**Testy** (`infra/tools/pool-ha/test-promote-guard.sh`, stubované SSH/parita, běží i na macOS):

```text
RESULT: 22 pass, 0 fail
```

Pokrývá: primár active, timer active, zbytkový proces, nedostupný SSH, parita FAIL,
stratum odpovídá, vše OK, token+cooldown, druhý promote s aktivním tokenem, release,
držení cooldownu, povolení po cooldownu, audit záznamy, a režim sondy (`unit/proc/timer`).

**Live na produkci** (operátorský stroj, reálné boxy):

```text
$ ZION_POOL_HA_SSH="ssh zion-v6" ZION_DR_PARITY_SCRIPT=$PWD/scripts/ops/dr-parity-check.sh \
  DR_PRIMARY_HOST=zion-v6 DR_STANDBY_HOST=zion-edge2 \
  bash infra/tools/pool-ha/pool-promote-guard.sh --check
pool-promote-guard: promote BLOKOVÁN G1✗ G2✗ G3✗ G4✓ G5✓ G6✓
  ✗ G1 unit active → primár ŽIJE (degradace není smrt, restartuj ho)
  ✗ G2 zion-v31-watchdog.timer je active → vzkřísil by pool
  ✗ G3 stratum 62.171.141.136:8444 ODPOVÍDÁ → minery by pendlovaly
  ✓ G4 parita bez FAIL
  ✓ G5 žádný token
  ✓ G6 cooldown ok
exit=1
```

Guard na EDGE2 přes omezenou sondu hlásí `unit=active proc=1 timer=active` a promote
zablokuje; G4 tam záměrně selhává (standby nemá shell na primáru) — autoritativní verdikt
vydává operátorský stroj, token se na standby synchronizuje (`ZION_PROMOTE_TOKEN_SYNC`).

## 6. Meze / co zůstává

- **Auto-promote (armed) neexistuje** a v tomto okně se nedělá — promote je manuální;
  guard jen garantuje, že bez splněných podmínek neprojde. Flip na auto = samostatné rozhodnutí 👤.
- **Token platí 15 min** (`ZION_PROMOTE_TOKEN_TTL_S`). Po vypršení je potřeba nový `--promote`.
- **G4 závisí na dosažitelnosti primáru** z místa, kde guard běží. Z EDGE2 to nejde (záměr);
  z operátorského stroje ano.
- **Split-brain detekce** (dvě aktivní instance proti sobě) není součástí guardu — pokrývá ji
  kombinace G2 (auto-restart pryč) + G3 (stratum zavřený) + G5 (single-flight token). Kdyby se
  jednou zaváděl armed mód, sem patří sdílený lease (např. v Postgresu) místo souboru.
