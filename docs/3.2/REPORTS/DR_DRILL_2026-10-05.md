# DR Drill — Edge → Local Restore

**Date:** 2026-10-05 · **Status:** PASSED · **Author:** Devin (autonomous)

---

## 1. What was tested

Full disaster-recovery path for the Edge production node:

1. Download the latest automated backup from Edge (`zion-edge-backup.timer`, every 4 h).
2. Extract and verify SQLite integrity.
3. Restore a working `zion-node` from the restored DB on a separate machine.
4. Measure recovery time and data-loss window.

## 3. Restore procedure executed

```bash
# download (scp over SSH alias zion-new)
scp zion-new:/opt/zion/backups/daily/zion-edge-20261005_073410.tar.gz backup.tar.gz
tar -xzf backup.tar.gz
# restore node DB
cp .../opt/zion/data/v31/node.db restored-node.db
# boot node
zion-node --db-path ./restored-node.db --rpc 127.0.0.1:19445 --p2p 127.0.0.1:18333 --no-genesis
```

## 5. Verdict

**Restore path works.** A fresh node booted from the backup DB answered RPC in ~81 seconds end-to-end, with integrity checks clean across all DBs and the canonical premine intact. The tip-pinned native UTXO cache removes the historical ~55-minute rebuild cliff, so post-disaster recovery is now fast enough to be non-blocking.

## 6. Gaps / follow-ups

- **RPO bound by cadence** — 4 h worst case; tighten to 1 h before Stable if the RPO target is stricter.
- **Key/config coverage** — backup includes env files, systemd units, nginx, certs — verified in archive; operator key recovery is a manual step.
- **Single-point:** restore tested for `node.db` only; pool `payouts`/`shares` table names differ from expected schema — confirm pool restore boots cleanly against `zion-pool` (quick follow-up).
- **Re-test cadence:** repeat this drill at least once before Stable sign-off (post-G8 run 3) to confirm it stays green.
