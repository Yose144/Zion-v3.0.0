## 1. Context & Origin

This document captures the complete OASIS Web frontend work done in this thread and the agreed next steps. It is intended to preserve the full technical context for future sessions, other agents, and the migration toward UE5 / native OASIS clients.

OASIS Web is the **public visual entry point** for the ZION multiverse: a static-export Next.js 16 + React 19 + React Three Fiber application that lets the user fly through a generated 3D galaxy, inspect 55 OASIS worlds, and eventually enter individual worlds as mini 3D scenes.

The work began from an earlier conversation state where the `WarpIntro`, `TreeOfLife`, `GalaxyCore`, and `GalaxyMap` were already present, and the goal was to visualize all 55 generated worlds professionally.

## 2. What Has Been Built

### 2.1 Data & Domain

- `src/domain/config/worlds.ts` now contains all 55 OASIS worlds.
- Each world has a deterministic `galaxyPosition` (x, y, z) generated by `scripts/generate-worlds-config.py`.
- `src/domain/ports/random.ts` provides a portable, seeded `createRandom` PRNG (mulberry32) used everywhere instead of `Math.random()` to keep the galaxy deterministic across React/Three and future UE5 builds.
- `src/domain/quests.ts` added: per-world deterministic quest generator with category-based templates (exploration, combat, harvest, puzzle, social).

### 2.2 3D Galaxy (`src/components/`)

- **GalaxyMap.tsx** — renders all 55 worlds, category filter, selected world, constellation lines to the core, and now the `Hyperlanes` network.
- **World.tsx** — individual world node: sphere, glow aura, rotating ring, category badge, hover/selected card, always-visible labels for star systems, and now an oriented **warp-gate torus**.
- **Hyperlanes.tsx** — nearest-neighbor warp-gate connections between worlds with additive, pulsing lines.
- **Galaxy.tsx / GalaxyCore.tsx / TreeOfLife.tsx / Nebula.tsx** — background galaxy, Contact-inspired core, Fountain-inspired tree, and nebula fog.
- **SelectionBeacon.tsx** — pulsing beam and ring around the focused world.
- **CameraRig** (inside `OasisScene.tsx`) — cinematic flights for intro, world focus, and world entry; FOV lerp, damping, `minDistance`/`maxDistance`, can be disabled for flight mode.

### 2.3 World Entry (`src/components/`)

- **WorldPanel.tsx** — slide-in detail panel with name, category, location, vibe, summary, tags, Golden Egg clue, archetype, and generated quests.
- **WorldFilter.tsx** — bottom category filter with counts and visible-world counter.
- **WorldEnvironment.tsx** — procedural 3D world view per category:
  - `star-system` — glowing star with corona sprites, orbiting satellites.
  - `planet` / `world` — procedural canvas planet texture, atmosphere, rings, moons.
  - `sector` — dodecahedron with wireframe overlay.
  - `dimension` — torus-knot wireframe with additive duplicates.
- **WarpFlash.tsx** — full-screen warp flash on entering a world.

### 2.4 Intro & UI

- **WarpIntro.tsx** — canvas-based deterministic multispectrum warp starfield, cinematic vignette, Carl Sagan quote, progress bar while warping.
- **OasisClient.tsx** — orchestrates phases (intro/arrival/rite/scene), filters, selected world, world view, audio, flight mode, responsive layout, UI hide/show toggle (H key).
- **PilgrimRite.tsx** — 3-step onboarding: Morpheus (red/blue pill) → Avatar customization (callsign, body type, neon accent, augmentation) → Archetype selection (warrior/trader/explorer/sage with bonuses).
- **OasisHud.tsx** — API status panel (now uses relative API paths when `NEXT_PUBLIC_OASIS_API_URL` is empty for edge deploy).
- **OasisScene.tsx** — Canvas root, conditional galaxy/world rendering, post-processing Bloom.
- **WorldFilter.tsx** — vertical right-side panel with category filters and Galactic Layers (1-5) filtering.
- **GamePanel.tsx** — tabbed settings panel (Ship, Identity, Audio, OASIS) with ship model selector, upgrades, hull color, avatar config summary, wallet management.

### 2.5 Audio

- **AudioEngine.tsx** — Web Audio ambient drone, brown-noise wind layer, warp sweep effect, mute toggle, localStorage persistence.

### 2.6 Flight / In-Game Controls

- **FlightControls.tsx** — `PointerLockControls` + custom WASD/QE/Space/Shift movement. Exposes `lock()`/`unlock()` via `useImperativeHandle` so the UI can request pointer lock from a real user gesture.
- **Flight HUD in OasisClient** — crosshair, live speed readout, boost bar, controls cheat-sheet, Exit button.

### 2.7 Deployment

- `deploy/deploy-oasis-web.sh` builds a static export and rsyncs `dist/` to `/var/www/oasis` on the Edge server, reloads nginx, runs a health check.
- `deploy/nginx-oasis.conf` serves the static export and proxies `/health` and `/api/` to the local OASIS backend.

### 2.8 Gameplay, Progression & Backend Sync

- **gameStore** — persistent (localStorage) player state: `xp`, `credits`, `completedQuests`, `discoveredWorlds`, `scannedWorlds`, `collectedEggs`, `shipLoadout` (with `model` field for STL ships), `avatarConfig` (callsign, bodyType, neonColor, augmentation), `archetype`.
- **PlayerHud** — level, XP bar, credits, completed quests, discovered worlds, live quests, linked wallet address with type badge.
- **WorldPanel** — real backend quests with avatar cards, quest completion, Golden Egg claim.
- **PilgrimShip** — visible in flight, loads STL ship models (A-Wing, B-Wing, Snowspeeder, TIE Fighter, TIE Interceptor) via STLLoader, color/thruster changes based on `shipLoadout`.
- **ShipLoadout / GamePanel ShipTab** — upgrade engine/cargo/scanner, pick hull color, select vessel chassis from 6 ship models.
- **AudioEngine** — procedural chord pad, random space chimes, SFX for quest complete, scan, approach.
- **Toast / feedback UI** — notifications for key actions.
- **OnboardingHint** — dismissible first-visit overlay with controls, flight, quests, eggs, wallet hints.
- **OasisHud** — live connection, manual refresh, error state, leaderboard, hot territories.
- **ZION Wallet Login** — `zion1` address validation, mnemonic import, in-browser wallet generation (same derivation as desktop agent / V3 core).
- **Backend sync** — `awardPlayerXp` and `completePlayerQuest` API calls; local XP synced from `getPlayer`.

## 4. Current Architecture

```
OasisClient (state orchestration)
├── OasisScene (Canvas)
│   ├── Galaxy view
│   │   ├── Galaxy / GalaxyCore / Nebula / TreeOfLife
│   │   ├── Hyperlanes
│   │   ├── GalaxyMap (55 World nodes)
│   │   └── SelectionBeacon (if selected)
│   ├── World view
│   │   └── WorldEnvironment (with NPC hologram + PilgrimShip)
│   ├── CameraRig (OrbitControls + cinematic flights)
│   └── FlightControls (PointerLockControls) [when flightMode]
├── WorldPanel (selected world info, real backend quests, Golden Egg, NPC card)
├── WorldFilter (category filter)
├── OasisHud (API status, leaderboard, hot territories)
├── PlayerHud (player level, XP, credits, wallet address, ship loadout/settings buttons)
├── ShipLoadout (upgrade engine/cargo/scanner, change hull color)
├── PlayerSettings (pilgrim ID or ZION wallet link/import/generate)
├── OnboardingHint (dismissible first-visit guide)
├── ToastContainer (feedback notifications)
├── AudioEngine (ambient, engine drone, boost, SFX)
└── WarpFlash (world entry effect)
```

State shape in `OasisClient`:
- `phase`: `intro` | `arrival` | `scene`
- `view`: `galaxy` | `world`
- `selectedWorld: World | null`
- `activeCategories: WorldCategory[]`
- `flightMode: boolean`
- `flightSpeed: number`

Persistent game state in `gameStore` (localStorage + backend sync):
- `address`, `xp`, `credits`, `completedQuests`, `discoveredWorlds`, `scannedWorlds`, `collectedEggs`
- `shipLoadout` (boost / cargo / scanner / color)
- `realQuests`, `avatars`, `territories` (fetched from API)

## 7. How to Build & Deploy

Local:
```bash
cd APP&WEB/OasisWeb
npm install   # if needed
npm run build
python3 -m http.server 3001 --directory dist
```

Deploy to Edge:
```bash
bash APP&WEB/OasisWeb/deploy/deploy-oasis-web.sh
```

The script will:
1. Build with `NEXT_PUBLIC_OASIS_API_URL=` (relative API paths for edge).
2. Rsync `dist/` to `root@62.171.141.136:/var/www/oasis` on port `2222`.
3. Copy `deploy/nginx-oasis.conf` to `/etc/nginx/sites-enabled/oasis.zionterranova.com.conf`.
4. Run `nginx -t && nginx -s reload`.
5. Health-check `https://oasis.zionterranova.com/`.
