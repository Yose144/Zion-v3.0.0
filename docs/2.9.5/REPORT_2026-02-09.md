## ✅ Provedené opravy

### Fix #1 — Deterministické CHv3 hashování

| | |
|---|---|
| **Soubory** | `cosmic-harmony/src/algorithms.rs`, `cosmic-harmony/src/engine.rs` |
| **Problém** | `golden_matrix()` a `cosmic_fusion()` používaly `f64` floating-point, který dává různé výsledky na různém HW (x86 vs ARM, MSVC vs GCC). Miners a validátoři se neshodli na hashi. |
| **Řešení** | Obě funkce nyní delegují na `algorithms_opt::golden_matrix_opt()` / `cosmic_fusion_opt()` — fixed-point aritmetika (u64, bitové operace). 100% deterministické na všech platformách. |
| **Testy** | +4 cross-impl testy ověřující byte-exact shodu legacy vs opt pro různé vstupy |

### Fix #2 — DEV_MODE bezpečnostní brána

| | |
|---|---|
| **Soubory** | `core/src/blockchain/validation.rs`, `core/src/jsonrpc/mod.rs` |
| **Problém** | `ZION_DEV_MODE=1` env proměnná obcházela PoW validaci a umožňovala `dev.set_difficulty` / `dev.credit_balance` i v produkci. Útočník mohl vytvářet bloky bez mining. |
| **Řešení** | `#[cfg(debug_assertions)]` — DEV funkce existují POUZE v debug buildech. Release binárky je kompletně vynechají na úrovni kompilátoru. |

### Fix #3 — LWMA DAA verifikace

| | |
|---|---|
| **Soubory** | `core/src/state/mod.rs` |
| **Problém** | `process_block()` používalo jednoduchý single-block `calculate_next_difficulty()` místo plného LWMA s 60-block oknem. Difficulty se neadjustovala správně. |
| **Řešení** | Nahrazeno plným LWMA voláním `lwma_next_difficulty()` s 60-block oknem z LMDB storage. Difficulty se nyní adjustuje správně (±25% clamp per block). |

### Fix #4 — Validace premine adres

| | |
|---|---|
| **Soubory** | `core/src/blockchain/premine.rs` |
| **Problém** | Premine tabulka (12 adres, 16.78B ZION) neměla runtime validaci — překlep v adrese = ztráta tokenů navždy. |
| **Řešení** | 2 nové testy: `test_all_premine_addresses_valid_format` (každá adresa validní `zion1...` 44 znaků), `test_no_duplicate_premine_addresses` (žádné duplicity). |

### Fix #5 — UTXO Undo Log (🆕 dnes)

| | |
|---|---|
| **Soubory** | `core/src/storage/lmdb.rs` |
| **Problém** | Při reorganizaci blockchainu `rollback_block_utxos()` rekonstruoval spotřebované UTXO traversováním celého chainu: `tx_to_block → blocks → find_tx → output`. Pomalé, křehké, mohlo tiše selhat pokud blok nebyl nalezen. |
| **Řešení** | Nová LMDB databáze `undo_blocks` (height → `BlockUndoData`). Při `apply_block_utxos()` se každé UTXO **před smazáním** uloží do undo záznamu. Rollback pak jednoduše přečte undo data a obnoví UTXO — O(1) lookup místo O(chain_length). |
| **Nové API** | `get_undo_data(height)`, `prune_undo_data(finalized_height)` |
| **Fallback** | Bloky aplikované před upgradem → automatický fallback na legacy metodu |
| **Testy** | +10 testů: apply/rollback/multi-block-chain/multi-input/prune/delete-cleanup/hash-check/idempotence |

### Fix #6 — Pool Windows kompilace

| | |
|---|---|
| **Soubory** | `pool/src/main.rs` |
| **Problém** | `tokio::signal::unix::signal(SIGTERM)` neexistuje na Windows → kompilace selhala. |
| **Řešení** | `#[cfg(unix)]` / `#[cfg(not(unix))]` podmíněný kód. Windows používá pouze `ctrl_c()`. |

### Fix #7 — Checksum adres

| | |
|---|---|
| **Soubory** | `core/src/crypto/keys.rs` |
| **Problém** | Adresy `zion1...` neměly checksum — překlep v adrese = ztráta prostředků bez varování. |
| **Řešení** | Nový formát: `zion1` (5 znaků) + body (35 znaků) + checksum (4 znaky) = 44 znaků. Checksum = SHA-256(body) → první 4 base32 znaky. `is_valid_zion1_address()` ověřuje checksum, `is_valid_zion1_address_format()` zpětná kompatibilita. |
| **Testy** | +12 testů: délka, prefix, round-trip (256 seedů), mutace, zkrácení, determinismus |

### Fix #8 — RPC autentizace

| | |
|---|---|
| **Soubory** | `core/src/rpc/auth.rs` (NOVÝ), `core/src/rpc/server.rs`, `core/src/rpc/mod.rs` |
| **Problém** | JSON-RPC endpointy (`submit_block`, `submit_tx`) byly veřejně přístupné — kdokoli mohl injectovat transakce. |
| **Řešení** | Bearer token middleware pro Axum. `ZION_RPC_TOKEN` env proměnná, constant-time porovnání. Write endpointy chráněné, read endpointy (`/stats`, `/health`) veřejné. Bez tokenu = otevřený přístup (zpětná kompatibilita pro testnet). |
| **Testy** | +2 testy v `auth.rs` |

|---|---|
