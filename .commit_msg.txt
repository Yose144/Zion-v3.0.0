feat(L1): add memo support to UTXO SendParams + build_and_sign

Previously `zion wallet send --memo` accepted the flag but silently
dropped the memo for UTXO transactions, because `SendParams` had no
`memo` field and `build_and_sign` hardcoded `memo: None` on every
output.  This trapped 100M ZION on the bridge vault: the relay
detected the lock but could not mint wZION because the EVM recipient
was missing.

User-approved L1 change (per AGENTS.md security protocol).

Changes:
- `V3/L1/core/src/wallet.rs`: add `memo: Option<String>` to
  `SendParams`; thread it into the primary output of `build_and_sign`.
  Change outputs still carry `memo: None` (consensus rule: change
  outputs must not carry memos).
- `V3/cli/src/commands/wallet.rs`: pass `--memo` into `SendParams`.
- `V3/sdk/src/wallet.rs`: default `memo: None` in existing helper.
- `V3/L1/core/src/bin/wallet.rs`: default `memo: None` in `cmd_send`
  (the dedicated `bridge-lock` subcommand already builds memo-carrying
  outputs manually).
- All unit tests in `wallet::tests` updated to construct `SendParams`
  with `memo: None`.

Verification: `cargo test -p zion-core --lib wallet` → 14 passed, 0
failed.
